# 신입 교육 준비 현황 만들기

프로젝트 `CLAUDE.md`의 공통 규칙을 모든 단계에 적용한다. 판정 기준은 `질문-기준.md`, 양식은 `templates/`에 있다(이 스킬 폴더 기준).

## 0. 준비
1. 입력: `$ARGUMENTS`가 있으면 그 폴더(안의 `*.md`) 또는 glob, 없으면 프로젝트 루트의 `회의-녹취-*.md`.
2. 파일이 0개면 멈추고 사용자에게 알린다.
3. 각 파일 머리의 회차·날짜로 순서를 정한다. 회차가 없으면 날짜, 날짜도 없으면 파일 이름 순. 정한 순서를 사용자에게 한 줄로 보여 준다.
4. 출력 폴더 `산출물/<오늘 YYYY-MM-DD>/`를 정한다. 이미 있으면 `-2`, `-3`… 을 붙인다. 이전 결과는 건드리지 않는다.

## 1. 회의록 — minutes-writer를 회의마다 따로, 한꺼번에
- **한 메시지에서** 녹취 개수만큼 `minutes-writer` 에이전트를 병렬로 부른다.
- 각 호출에는 그 회의의 녹취 경로, 회차, 출력 경로(`<출력>/회의록/회의록-<회차>.md`), 양식 경로(`.claude/skills/training-status/templates/회의록.md`)만 준다. 다른 회의 내용이나 이 스킬의 판정 기준은 주지 않는다(회의끼리 섞이거나 미리 맞춰지는 것을 막기 위해).
- 모두 끝나면 회의록 파일이 녹취 수만큼 있는지 확인한다. 빠진 것은 그 회의만 다시 부른다.

## 2. 대조표 — 메인이 직접
1. 회의록을 모두 읽는다.
2. `templates/대조표.md` 양식으로 항목 × 회의 표를 만든다. 항목은 회의록에 나온 것만.
3. `질문-기준.md`의 판정 절차를 유형 1 → 2 → 3 순으로 **모든 행에** 밟는다. 판정이 애매하면 원본 녹취를 직접 열어 확인한다.
4. 유형 3은 셈을 `셈한 것` 표에 식으로 남긴다.
5. `<출력>/대조표.md`로 쓴다.

## 3. 현황 — 메인이 직접
1. `templates/현황.md` 양식으로 `<출력>/현황.md`를 쓴다.
2. `여쭐 것`에는 대조표에서 유형 1·2·3으로 판정된 것만, `질문-기준.md`의 "쓰는 법"대로 올린다.
3. 나머지는 현황 표와 남은 일로. 단순 미정은 상태 칸에 "미정"으로만.
4. 인용은 원본 녹취 원문 그대로인지 다시 본다.

## 4. 검증 — status-verifier
1. `status-verifier`를 부른다. 원본 녹취 경로 전부, `현황.md`·`대조표.md` 경로, 기준 파일 경로(`.claude/skills/training-status/질문-기준.md`), 출력 경로 `<출력>/검증.md`를 준다. 메인의 판단 과정이나 "이건 맞을 것"이라는 설명은 주지 않는다.
2. FAIL·MISSING이 있으면: 원본 녹취로 확인한 뒤 맞는 지적만 반영해 대조표와 현황을 고친다. 반영하지 않은 지적은 이유를 `검증.md` 끝 `## 메인 의견` 절에 적는다.
3. 고쳤으면 검증을 한 번 더 돌린다. **최대 2회.** 그래도 남은 것은 숨기지 않고 사용자에게 보고한다.

## 5. 사용자에게 보고
- 산출물 경로 네 가지
- 여쭐 것 개수와 한 줄씩 제목
- 검증 결과(PASS/FAIL), 남은 지적과 `## 애매함` 항목
- 현황을 팀장님께 보내지는 않는다. 보내는 것은 사용자가 한다.
