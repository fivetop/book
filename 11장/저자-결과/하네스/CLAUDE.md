# 신입 교육 준비 현황 하네스

매달 바뀌는 회의 녹취로 **회의록(회의마다 1개)** 과 **팀장님께 올릴 현황 한 장** 을 만든다.

## 돌리는 법

```
/training-status                 # 프로젝트 루트의 회의-녹취-*.md 전부
/training-status 녹취/2026-08     # 다른 폴더나 glob을 줄 때
```

결과는 `산출물/<실행일 YYYY-MM-DD>/` 아래에 생긴다. 이미 있으면 `-2`, `-3`을 붙여 새로 만든다(이전 달 결과를 덮어쓰지 않는다).

```
산출물/2026-11-11/
  회의록/회의록-1.md … 회의록-N.md   ← minutes-writer가 회의마다 따로 씀
  대조표.md                          ← 항목 × 회의 표 (현황의 근거)
  현황.md                            ← 팀장님께 올릴 한 장
  검증.md                            ← status-verifier의 검증 결과
```

## 구성

| 파일 | 역할 |
|---|---|
| `.claude/skills/training-status/SKILL.md` | 전체 순서(오케스트레이션). 메인 세션이 따른다 |
| `.claude/skills/training-status/질문-기준.md` | 팀장님께 "꼭 물어야 할 것" 세 가지의 판정 기준 |
| `.claude/skills/training-status/templates/` | 회의록·대조표·현황 양식 |
| `.claude/agents/minutes-writer.md` | 녹취 1개 → 회의록 1개 |
| `.claude/agents/status-verifier.md` | 현황을 원본 녹취와 대조해 검증 |

## 모든 단계에 공통인 규칙

1. **녹취에 없는 것은 쓰지 않는다.** 추측·보충·일반 상식으로 빈칸을 채우지 않는다. 모르면 "녹취에 없음"이라고 쓴다.
2. **모든 사실에 근거를 단다.** 형식: `[3회] 박 대리: "여덟 명까지 돼요."` — 따옴표 안은 녹취 원문을 한 글자도 바꾸지 않고 옮긴다(검증 단계에서 원문 검색으로 확인한다).
3. 녹취에 연도·요일이 없으면 계산해서 붙이지 않는다. 계산(인원 합, 날짜 차이 등)을 했으면 식을 같이 적는다.
4. 말끝이 흐리거나("~였던 것 같아요", "그랬나?") 되묻고 넘어간 말은 확정으로 바꾸지 않고 그대로 불확실하다고 적는다.
5. 안건과 무관한 잡담은 적지 않는다.
6. 하네스는 파일만 만든다. 현황을 팀장님께 보내거나 메일·메신저로 내보내는 일은 사용자가 직접 한다.
